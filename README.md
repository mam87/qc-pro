# QC Pro — نظام ضبط الجودة المتكامل للمختبرات الطبية

تطبيق ويب عربي (RTL) يعمل على **GitHub Pages** مع قاعدة بيانات وتسجيل دخول عبر **Supabase** (مجاني).

## المزايا
- **الحسابات والصلاحيات**: تسجيل بالبريد وكلمة المرور، استعادة كلمة المرور. أول حساب يُنشأ = **مدير النظام (Admin)**، وكل حساب جديد يبقى "بانتظار الموافقة" حتى يفعّله المدير. الحماية مطبّقة داخل قاعدة البيانات (RLS) وليس في الواجهة فقط.
- **إدخال QC** لكل المستويات في التشغيل نفسه مع تقييم فوري بقواعد **Westgard** (1₂ₛ، 1₃ₛ، 2₂ₛ، R₄ₛ، 2/3₂ₛ، 3₁ₛ، 4₁ₛ، 6ₓ–12ₓ، 7T) داخل المادة وعبر المستويات، قابلة للتخصيص لكل فحص، والإجراء التصحيحي إلزامي عند الرفض.
- **مخطط Levey-Jennings** لكل لوت + مخطط Z-score لكل المستويات، تصدير PNG، طباعة.
- **الإحصاء**: Mean، SD، CV%، Bias%، الإحصاء التراكمي للوت، اختبار **Grubbs** للقيم الشاذة، واعتماد متوسط/SD المختبر بعد ≥20 نقطة (CLSI C24).
- **Six Sigma**: حساب σ لكل فحص/مستوى، **QGI**، مخطط قرار الطريقة المُعيَّر، وتوصيات **Westgard Sigma Rules** (القواعد، N، التكرار).
- **EQA / PT**: الانحراف%، **SDI**، الحكم بالقبول حسب TEa، مخطط SDI.
- **عدم اليقين في القياس (MU)** بمنهجية Top-down وفق ISO 15189:2022 و ISO/TS 20914.
- **مقارنة اللوتات** (Crossover) للتحقق من لوت جديد.
- **تقرير شهري** قابل للطباعة/PDF مع خانات توقيع، وتصدير CSV.
- **سجل نتائج ومراجعة** يعتمد فيه المدير الإجراء التصحيحي.
- **سجل تدقيق (Audit trail)** تلقائي لكل إضافة/تعديل/حذف من قاعدة البيانات.
- لوحة تحكم بالتنبيهات: لوتات قاربت الانتهاء، فحوص لم يُسجَّل لها QC اليوم، رفض بانتظار المراجعة.

## التشغيل (15 دقيقة)

### 1) Supabase
1. أنشئ مشروعاً مجانياً على <https://supabase.com>.
2. **SQL Editor → New query** والصق محتوى `supabase/schema.sql` كاملاً ثم **Run**.
3. **Project Settings → API**: انسخ `Project URL` و `anon public key`.
4. **Authentication → URL Configuration**: ضع رابط موقعك (مثل `https://mam87.github.io/qc-pro/`) في **Site URL** و **Redirect URLs**.
5. (اختياري) **Authentication → Providers → Email**: يمكنك إيقاف *Confirm email* لتسهيل التجربة؛ الموافقة من المدير تبقى مطلوبة على أي حال.

### 1-ب) تفعيل تعدد المختبرات (v2)
في **SQL Editor** شغّل بعدها الملف `supabase/migration_v2_multitenant.sql` (آمن على قاعدة فيها بيانات، ويمكن تشغيله أكثر من مرة).
- أقدم مدير يصبح **مالك المنصة (superadmin)**، وتنتقل كل البيانات الحالية إلى مختبر افتراضي برمز `MAIN`.
- كل مختبر معزول تماماً عن غيره داخل قاعدة البيانات (RLS).

### 2) الإعداد
افتح `js/config.js` وضع:
```js
export const SUPABASE_URL = 'https://xxxx.supabase.co';
export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
export const LAB_NAME = 'مختبرات مستشفى ...';
```
> مفتاح `anon` مصمَّم ليكون علنياً؛ لا تضع أبداً مفتاح `service_role` في الموقع.

### 3) GitHub Pages
1. أنشئ مستودعاً جديداً (مثل `qc-pro`) وارفع كل الملفات كما هي.
2. **Settings → Pages → Deploy from a branch → main / root → Save**.
3. افتح الرابط، وأنشئ **حسابك أولاً** ليصبح حساب المدير.

### 4) أول استخدام
**الإعدادات** ← أضف الأقسام ← الأجهزة ← الفحوص (مع TEa والقواعد) ← لوتات QC (Mean و SD المستهدف). بعدها يستطيع المستخدمون المفعَّلون إدخال النتائج.

## إضافة عميل (مختبر) جديد
1. ادخل بحساب مالك المنصة ← **المختبرات المشتركة** ← **مختبر جديد**: الاسم، رمز التسجيل (مثل `ELITE`)، الباقة، عدد المستخدمين، تاريخ انتهاء الاشتراك.
2. زر ✉️ يولّد رسالة دعوة جاهزة فيها الرابط والرمز.
3. أول من يسجّل بالرمز يصبح **مدير المختبر**، ويوافق هو على حسابات فريقه.
4. زر ⤵️ ينقلك للعمل داخل أي مختبر لتجهيزه (تحميل الأقسام والفحوص القياسية، اللوتات) أو للدعم.
5. عند انتهاء الاشتراك أو إيقافه يتوقف الدخول لمستخدمي ذلك المختبر فوراً، وتبقى بياناتهم محفوظة.
